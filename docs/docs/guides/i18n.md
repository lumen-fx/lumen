# Translation

Lumen translates an app in four steps: mark the strings you want translated,
extract them into a catalogue, translate the catalogue, and run. Catalogues are
[Fluent](https://projectfluent.org/) `.ftl` files in a `locale/` directory
beside your markup.

## 1. Mark the strings

In markup, add `translatable` with a catalogue key. Keep the source-language
text in `text`; it is what shows until a translation exists:

```html
<label translatable="app-title" text="Weather"/>
<button id="refresh" translatable="action-refresh" text="Refresh"/>
```

`translatable` works on any element that displays text.

In a script, wrap the string in `t()`:

```rhai
set_text("status", t("status-loading"));
```

`tr()` is the same function under the Qt spelling. In candela both live in the
`lumen` namespace: `lumen::t("status-loading")`.

## 2. Extract

```sh
lumenc i18n extract ./myapp
```

This walks the app directory, reads every `.lmn`, `.rhai`, `.lua`, and `.cdl`
file, and writes the keys it finds to `locale/en-US.ftl`. Pass `--lang` to
target a different file:

```sh
lumenc i18n extract ./myapp --lang de-DE
```

Each new key is appended with a marker and its own key as the placeholder
value:

```ftl
# TODO: translate
app-title = app-title
```

Extraction is safe to re-run. Existing entries are copied through untouched, so
your translations survive; only keys missing from the file are added. Keys you
delete from your source stay in the catalogue until you remove them yourself.

## 3. Translate

One file per locale, named by its BCP-47 tag, directly inside `locale/`:

- `locale/en-US.ftl`
- `locale/de-DE.ftl`
- `locale/ja-JP.ftl`

Fill in the values:

```ftl
app-title = Wetter
action-refresh = Aktualisieren
```

Fluent's selector syntax handles plurals inside the catalogue:

```ftl
items = { $count ->
    [one] { $count } item
   *[other] { $count } items
}
```

Selectors that take a variable, like the one above, are filled in by Rust SDK
apps. A markup app's `t("items")` passes no variables, so the placeable stays
unresolved; write separate keys for the cases you need.

## 4. Run

The active locale is, in order:

1. `[app] locale` in `lumen.toml`
2. the desktop's locale
3. `en-US`

```toml
[app]
locale = "de-DE"
```

The value must be a valid BCP-47 tag; a malformed one fails at startup.

When a key is missing from the active locale, Lumen falls back to `en-US`, then
to the element's own `text` attribute, then to the key itself. Fallback is per
message, so a partly translated catalogue works: translated messages appear
translated, the rest read in English.

Naming a locale with no catalogue file is not an error. Every message falls
back, and the app runs in English.

On the web, `translatable` is resolved when the site is emitted, so a page
arrives in its language with nothing running. A build writes one document tree
per locale; under `render = "ssr"` it writes none and each request is rendered
in the locale it asks for. See [the web target](web.md) and
[rendering on a server](server-rendering.md).

## While developing

`lumenc run` watches the `locale/` directory. Editing a `.ftl` file, adding one,
or deleting one reloads the app with the new strings.

## Right-to-left text

Set the writing direction on the root of a page:

```html
<root dir="rtl">
```

`dir` accepts `ltr`, `rtl`, and `auto`, and it inherits, so you can flip a
single subtree. Direction does not follow the locale on its own; an Arabic or
Hebrew catalogue still needs `dir="rtl"`.

`lang` tags a subtree's language for text shaping:

```html
<label lang="ja" text="..."/>
```

## Limits today

- The locale is chosen at startup. Changing it means editing `lumen.toml` or the
  desktop setting and restarting.
- `translatable` replaces an element's text. A `placeholder` or a `tooltip` is
  shown as written.
- The fallback locale is `en-US` and cannot be changed.
- Locale-aware number, date, and currency formatting is available to Rust SDK
  apps; markup and scripts have no formatting call. See the
  [SDK reference](../reference/ffi.md).
- A script's `t()` returns the key it was given when a page is rendered on a
  server or prerendered by a build. Markup `translatable` is resolved in both.

The `lumenc i18n` flags are listed in the [CLI reference](../reference/cli.md),
and `[app] locale` in the [lumen.toml reference](../reference/lumen-toml.md).
