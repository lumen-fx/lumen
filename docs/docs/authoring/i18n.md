# Translation

A Lumen app ships its user-visible strings in translation catalogues instead
of hard-coding them in markup and script. You mark a string once, run one
command to collect every marked string into a catalogue file, hand that file
to a translator, and the app picks the translated strings up at startup.

Use this as soon as an app has more than one audience. Marking strings early
costs almost nothing; retrofitting it across a finished app means touching
every label.

The loop has three steps, and this page follows them: mark the strings,
extract them into a catalogue, translate the catalogue.

## Marking strings

In markup, `translatable="<key>"` marks an element's text:

```html
<column>
  <label translatable="app-title" text="Task list" />
  <button id="add" translatable="add-task" text="Add task" />
</column>
```

The key is a catalogue identifier, not display text. Keep it short and
kebab-case (`add-task`, `dialog-confirm-delete`).

The `text` attribute stays, and it is what the element shows when the key is
untranslated. That ordering is deliberate: translation wins, the authored
text is the fallback, and an element with a key but no text falls back to the
key itself, so a screen never renders blank because a catalogue is missing.

In script, call `t("<key>")`:

```candela
import "lumen.cdl";

fn on_start() {
    lumen::set_text("status", lumen::t("status-ready"));
}
```

```rhai
fn on_start() {
    set_text("status", t("status-ready"));
}
```

```lua
function on_start()
    set_text("status", t("status-ready"))
end
```

`tr("<key>")` is the same function under Qt's name, for authors who reach for
that spelling. Both return the key when nothing translates it.

The script form takes a key and nothing else. Interpolated values (`"3 items
selected"`) and plural forms are not wired to the script surface yet: build
those strings from a translated fragment plus your own formatting, or keep
them in markup where the value comes from a binding.

## Extracting a catalogue

```sh
lumenc i18n extract path/to/app
```

This scans the app's `.lmn`, `.cdl`, `.lua`, and `.rhai` files for marked
strings and writes `path/to/app/locale/en-US.ftl`, creating the directory if
it is not there. Pass `--lang de-DE` to write a different catalogue.

Re-running is safe. Entries already in the file are left exactly as they are,
and only newly found keys are appended, each with a placeholder value a
translator replaces:

```ftl
# TODO: translate
add-task = add-task
```

The scanner reads source text, so it finds keys written as literals. A key
assembled at runtime is invisible to it; add such keys to the catalogue by
hand.

## The catalogue

Catalogues live in `<app>/locale/`, one file per locale, named for the locale
it holds:

```text
myapp/
  main.lmn
  main.css
  locale/
    en-US.ftl
    de-DE.ftl
```

The format is [Fluent](https://projectfluent.org/), one `key = value` entry
per line:

```ftl
app-title = Aufgabenliste
add-task = Neue Aufgabe
status-ready = Bereit
```

A translated file is a copy of the extracted one with the values replaced.
Keys that a locale does not carry fall through to `en-US`, so a partly
translated app shows translated strings where they exist and English
elsewhere.

Every `.ftl` file in the directory is loaded at startup, whichever locale is
active. A filename that is not a BCP-47 tag stops the app from starting,
naming the file, rather than being quietly skipped.

Editing a catalogue while `lumenc run` is watching the app reloads it in
place, the same as editing markup or CSS.

## Choosing the locale

The active locale is, in order:

1. `[app] locale` in `lumen.toml`, when set.
2. The locale the operating system reports.
3. `en-US`.

Pin it when you want an app to start in one language regardless of the
machine:

```toml
[app]
locale = "de-DE"
```

A tag that is not valid BCP-47 is a `lumen.toml` error, so a typo surfaces at
startup instead of leaving the app silently in English.

## What is not covered yet

- Script translation takes a key only. Arguments and plural selection are
  Fluent features the catalogue can express, but the `t()` builtin does not
  pass values through yet.
- Text marked `translatable` is resolved once, when the element spawns.
  Switching locale in a running app needs a reload.
